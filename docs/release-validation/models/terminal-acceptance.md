# M8: границы переноса строгой M7 приёмки

Это read-only архитектурная рекомендация, не результат нового живого прогона. Не ослаблять существующие проверки [evaluator](../../../spikes/social-validation/evaluate.py): обычные независимые launch/process records и cleanup; уникальная accepted session каждого actor; совпадение frozen client proof, Runtime authoritative terminal и общей dedicated-server summary; корректный GameOver/replay и реальные игровые действия. Один текущий `socialPhase=GameOver`, supervisor exit 0 или заявленный Brain не заменяют эти проверки.

Для M8 дополнительно подтвердить фактический negotiated набор: game0.9.0, Arena0.6.0, Core/Standard1.0, Communication0.1.0. Admission4 — серверный контракт и не версия Core. Waiting players и TaskWork остаются owner-scoped session data; TaskStep должен быть фактически зарегистрированным ordered command. KillPresentation — разрешённый owner-event, не глобальный kill feed. В первоначальном Unity binding обнаружены четыре пропущенные регистрации; ранние model-попытки сохраняются как старое условие интеграции, без заднего числа приёмки новых механик.

Полные роли, replay и чужие private state допустимы только в авторизованном postgame. Runtime event policy проверяет self entity/recipient/match, допускает summary после authoritative GameOver и ограничивает массивы. До terminal closed episodes не публикуются. Terminal-only ledger может вернуть только ранее зафиксированные зарегистрированные Skill IDs в копию безопасного отчёта; args, outputs, контекст и сообщения должны остаться скрытыми. Старые отчёты без ledger не дополняются догадками.

M7 GameOver-проверки сами по себе не доказывают M8 resume или presentation privacy. Отдельно проверять credential rotation/connected denial, actor+match+generation binding, прежние life/duty, hydration own tasks, запрет stale-generation command, непрерывную уязвимость физического ghost и отсутствие resurrection. Frozen terminal proof должен соответствовать последней принятой session/generation; совпадение display name недостаточно. Для эффекта нужны собственные recipient/GUID/срок, текущий LOS и отсутствие повторного аудио/анимации после resume. Native 640 ms и слышимость не выводятся из JSON.

Для failed participation достаточно безопасных provider/version/turn/tool/usage-скаляров и ограниченного allowlist failure code; исключения, model replies, prompts и args не публиковать. Независимый official Codex start требует обычных game/process/session bindings плюс фактический pinned SDK turn и ноль direct tools; одно имя `codex` или положительный Participation `measured_tokens` недостаточно. Исторический `brain_failure` не превращается в `codex_usage_limit` только из-за превышения скаляром 500 000: разные бюджеты и сумма эпизодов требуют отдельного доказательства.
