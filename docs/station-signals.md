# Agents Arena Signal Console

Agents Arena **0.5.0** adds a small training console on the west side of Main Hall.
It uses the existing room atlas material and simple cyan/amber panel sprites.
The two-room world, doorway, owner prediction, character motor and input rates
remain the same. The original offline scene, character prefab and PNGs are preserved.

Human players within 1.6 units of the console's interaction point can press **E**
or click **Use Signal Console**. Its two buttons send **Routine Notice** and
**Urgent Recall**. The channel is explicitly a station-wide training broadcast;
it is not an emergency simulator or a chat system. A station notification is
visible on each connected client. ACTOR mode does not expose the Human buttons.

The console housing is at `(-2.6, -0.4)` and its interaction point at
`(-2.3, -0.65)`. The normal second player's capsule center is about 1.48 units
from that point, so a Human observer can use it from spawn. Its solid base stays
outside all sixteen spawn capsules and the existing navigation route.

## Authority and delivery

The Human UI calls the owned player's `NetworkStationSignals` component through
the existing authenticated NGO connection. The request contains only a signal
kind byte. A reliable owner-only server RPC verifies the current approved client,
that client's exact player NetworkObject, server actor identity, active console,
Main Hall membership, finite physical capsule-center distance, selected enum and
cooldowns. Each player waits two seconds between accepted signals; the station
also has a 0.75-second shared cooldown. Invalid requests create no event. Rejection
responses are limited to two per second per player.

Only the game server generates signal ID, source actor, target room, fixed text,
UTC timestamp and increasing console revision. Reliable server-only NGO RPC
delivery carries that bounded payload to current station-visible players. The
local console deduplicates revisions and notifies the game adapter, which uses
the existing generic typed event publisher and gRPC stream. There is no public
event-generation HTTP API, Runtime signal command, arbitrary text input or
diagnostic interaction bypass.

This demo deliberately makes its players station-visible. Its typed audience is
`STATION_WIDE`; a future private event must use a separate audience-filtered
delivery path. Signals are live events, not replayed to late joiners or a Runtime
that was disconnected when they happened. Existing bridge control-queue overflow
fails the session explicitly rather than silently dropping a signal.

## Extension contract

Only the Agents Arena extension changes, from **0.1.0 to 0.2.0**. ACTOR Core and
Standard remain unchanged at protocol 1.0 and extension 0.1.0; admission stays 3.
The new schema is additive and preserves all room field numbers and type URLs.
Installed required extensions still negotiate an exact package version/hash.

Capability: `agents-arena.station-signal` (Event).
Type: `type.googleapis.com/actor.extensions.agents_arena.v1.StationSignalEvent`.

| Field | Number | Meaning |
| --- | --- | --- |
| `signal_id` | 1 | Server-generated 32-character UUID, stable across bridge envelopes |
| `signal_kind` | 2 | `ROUTINE_NOTICE=1` or `URGENT_RECALL=2`; zero is unspecified |
| `source_actor_id` | 3 | Server identity of the approved Human's actor |
| `target_room_id` | 4 | `main-hall` |
| `message` | 5 | Fixed server text, at most 256 UTF-8 bytes |
| `server_unix_ms` | 6 | UTC creation time in Unix milliseconds |
| `audience` | 7 | `STATION_WIDE=1`; zero is unspecified |
| `server_revision` | 8 | Increasing revision for this match's console |

The outer event's entity is the source actor and its revision is the same
server revision. Bridge session/sequence remain separate transport ordering.
`signal_id` lets the Runtime deduplicate the same semantic event even when it is
seen under another envelope sequence. Event metadata describes gameplay;
classification disposition remains a Runtime policy, never a Protobuf enum here.

Python exports these constants and generated types from `actor_agents_arena`.
Schemas, C#/Python bindings, descriptors, fingerprint and resource metadata are
generated by `scripts/generate-proto.sh`; `--check` verifies all 37 artifacts.
The server-fixed messages are still external game data when passed to a Brain.

## Verification

`StationSignalTests` exercises rejected ownership/room/range/NaN/cooldown/action
facts, valid Routine/Urgent requests, bounded server identity/text/audience and
typed event publication through the existing SDK registry. Python tests verify
generated and descriptor-only decoding and typed delivery through a real local
duplex gRPC stream. The scene builder checks console identity, room, prefab RPC
endpoint and second-spawn reachability. The existing 58 geometry checks run again
with the console present, including actual physics, all spawns, both directions
through the doorway and the previous Human trapped-pose regression.

`--actor-report` retains safe diagnostic counters `stationSignals`,
`lastSignalId`, `lastSignalKind`, `lastSignalSourceActorId`, and
`lastSignalRevision` on either Human or Agent clients. These JSON reports are
diagnostics only. Native Human clicks and the authoritative Runtime event report
provide the real multiplayer acceptance evidence; local schema/rules tests alone
do not establish that end-to-end result.
