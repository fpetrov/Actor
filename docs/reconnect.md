# Authenticated Social reconnect

SocialDeduction reconnect is available after unexpected transport loss while the same client process retains its private credential. Explicit Leave and Runtime unavailability forfeit the actor and erase resume rights. A display name never establishes identity.

Admission protocol 4 assigns a random actor identity on initial join. The game server issues a short-lived, domain-separated HMAC resume credential bound to exact match, actor, player name consistency, game/admission versions, credential ID, connection generation and expiry. The credential travels only through a targeted owner RPC and remains in `MatchSession` memory. It is absent from Protobuf, SDK manifests, observations, model context, PlayerPrefs, public reports and logs.

The rate-limited CP resume endpoint checks the signature, match and expiry and rejects an actor reported as already connected. CP approval is not sufficient to take over an endpoint: the game server's bounded admission registry is the final guard. A connected binding always rejects a second connection. An admitted disconnected binding increments generation and rotates its credential. A credential from before rotation can recover a connection that failed before owner acknowledgement only while disconnected, unacknowledged and within the original expiry. Acknowledgement closes that fallback. Replaying a ticket nonce or issuing a stale-generation action cannot reuse the old command rights; generation is checked before the game action replay cache.

The transport grace defaults to 30 seconds and is independently bounded from the credential's expiry. The UI exposes credential expiry as a chance to **try** reconnecting, not a guaranteed recovery window. On unexpected loss the retained server-owned avatar halts. It cannot move, submit actions, progress work or vote, but remains physically present, observable and vulnerable. A legitimate kill or ejection during grace is irreversible. Resume preserves that own life, alignment, duty and submitted ballot; it does not resurrect. Expired grace forfeits irreversibly. Disconnect cancels active work, and a resumed actor needs a fresh own work ID and generation-bound action context.

Successful resume replaces the transport-owned player endpoint while preserving the authoritative actor's game state and last physical root. Per-client NGO interest remains in force. A fresh own-state generation and a matching own visible-world bundle are required before the SDK bridge starts. Other own bundles arrive through their targeted authoritative channels; task Skills require those typed observations. The live probe additionally waits for every required bundle before accepting recovery. A new room always receives fresh actor/match identity and cannot import another room's credential or role. Explicit Leave waits for the private revoke acknowledgement within a bound, shuts down networking, unloads the selected gameplay scene, and returns to Lobby before another join.

WaitingPlayers exposes only the public approved names, own actor identities, readiness and connected flag in a bounded six-player roster. On leaving that phase an explicit stable empty roster clears it. It never publishes alignment, duty, life, pose, Human/Agent mode or subsequent hidden disconnect revision counters.

The three own task mechanics share the same typed server rules for Human and agent:

- Maintenance requires a continuous authoritative stationary hold.
- Circuit calibration displays one target choice per step and rejects early, stale-step or wrong submissions. Three completed steps finish the original work request.
- Sensor observation withholds the second sample until its authoritative delay, then accepts the trend computed from both samples.

Every interactive step has a bounded deadline. A step receipt is distinct from overall completion: only the original work correlation's accepted **completed** result establishes completion. Cancellation accepts the own work ID or original start correlation; the own work observation explicitly clears after termination. Fake Impostor work uses the same activity surface and contributes no Crew progress. CP/server validate that the configured task threshold is feasible for the assigned Crew task count. Defaults are eight Crew tasks, a 12-second maintenance hold, 2.5-second calibration step, eight-second sensor wait and 30-second response deadline.

The admission-drain marker is checked under the same CP gate as Create, Join and Resume. Listing rooms also waits for this gate. Deployment can set the trusted marker, obtain a final allocation-complete room list, and stop only after a zero-room check without admitting a request queued during drain. The endpoint remains an ordinary read API; no public operator endpoint was added.

Pure SDK/CP regression tests cover signature domain separation, lifetime/binding bounds, connected takeover, rotation/acknowledgement failure, grace/forfeit/death semantics, stale action generation, roster clearing, all three task mechanics and admission-drain races. Independent source review found no concrete takeover or hidden-state leak blocker. The actual [resume probe](../spikes/social-resume/README.md) passed in an ordinary four-client staging match: a 30.09-second bidirectional UDP blackhole, same client process and own identity/assignment, higher generation, hydrated own bundles, authoritative old-generation rejection and fresh stopped motion. All ten recorded owned processes/groups were stopped. The [safe result](release-validation/network/reconnect.json) retains three supervisor attempts: two setup failures and one actual transport-fault pass. It does not establish native GUI recovery, post-death resume, a live vulnerable-ghost kill or whole-match success.
