# MiniLM v7: пересмотр плана агента

Модель решает один вопрос: **нужен ли новый стратегический ответ Brain/LLM после
полученного события?** `0` — продолжать принятый план, `1` — запросить пересмотр.
Она не выбирает игровое действие, не угадывает скрытые роли и не исполняет команды.

Пакет содержит веса, токенизатор, подготовку входа, провайдер Runtime, приватное
логирование и команды для проверки и дообучения. Runtime Core не зависит от PyTorch.
Подробности подключения и сбора данных: [INTEGRATION_AND_DATA.md](INTEGRATION_AND_DATA.md).
Исполнение принятого плана: [документ Runtime](../../docs/executable-plans.md).

## Модель

| Параметр | Значение |
| --- | --- |
| Версия | `minilm-v7-r2`, статус `development_only` |
| Исходные веса | `sentence-transformers/paraphrase-MiniLM-L3-v2` |
| Ревизия исходной модели | `4ca70771034acceecb2e72475f72050fcdde4ddc` |
| Архитектура | `BertForSequenceClassification`: 3 слоя, размер скрытого состояния 384, 2 класса, около 17,4 млн параметров |
| Что дообучено | Энкодер и классификационная голова; продолжение MiniLM v6 |
| Вход | `ClassifierInput` 0.1/0.2 → `features.render_canonical_v1`, до 512 токенов |
| Решение | `softmax(logits)[1] >= 0.5`; оценка не калибрована как вероятность |
| Обучение v7 | 2045 уникальных входов; 2 эпохи; AdamW, шаг `5e-6`, batch 8, seed `20261023`, взвешенная ошибка с балансировкой классов |
| Проверка при разработке | 290 входов, использованных для выбора и проверки кандидата |
| Запуск | Локальный CPU, 2 потока, без удалённого API |

Веса: `src/actor_minilm/checkpoints/v7/model/model.safetensors`, 69 568 832 байта.
SHA-256: `fd10238301587a517815ea573d5923731d768c4ded9e99f972e4b941a77f09ff`.
Параметры и контрольные суммы находятся в `report.json` и `manifest.json` рядом
с папкой `model/`. Происхождение и лицензия: [THIRD_PARTY_NOTICES.md](THIRD_PARTY_NOTICES.md).
Это прямое дообучение нейросети; SetFit и логистическая регрессия здесь не используются.

## Установка и проверка

Из корня Actor, Python 3.12, в отдельном окружении:

```sh
python3.12 -m venv .venv
.venv/bin/python -m pip install ./runtime './classifiers/minilm[test]'
.venv/bin/actor-minilm classifiers/minilm/examples/body-covered.json
.venv/bin/actor-minilm classifiers/minilm/examples/body-uncovered.json
.venv/bin/actor-minilm classifiers/minilm/examples/runtime-row.json --runtime-row
.venv/bin/python -m pytest classifiers/minilm/tests runtime/tests -q
```

Runtime следует устанавливать **из того же коммита**, что и пакет модели: одной
версии `0.8.0` недостаточно, чтобы определить наличие контракта исполнимых планов.
После установки загрузка весов и токенизатора выполняется только с диска.
Для одного предсказания без игры достаточно `pip install ./classifiers/minilm`.

Штатный `scripts/launch-social-agents.py` ищет исполняемый файл Runtime в
`build/runtime-venv/bin/actor-runtime`. Для запуска через этот скрипт создайте
окружение в `build/runtime-venv` и установите **оба** пакета туда вместо `.venv`.
Выбор Brain `codex` дополнительно требует extra `runtime[codex]`; модель MiniLM
сама по себе подписку или авторизацию LLM не заменяет.

## Подключение к игре

В собственной конфигурации Runtime выберите:

```json
{"classifier": {"provider": "minilm", "timeout": 1.5}}
```

Готовый фрагмент: [examples/cognitive-minilm.json](examples/cognitive-minilm.json).
Entry point `actor.classifiers:minilm` устанавливается пакетом. Brain/LLM и его
авторизация настраиваются отдельно. Установка пакета не меняет конфигурацию
развёрнутого сервера. Для отката выберите `provider: rules` и перезапустите свой Runtime.

Runtime создаёт провайдер через `await ClassifierRegistry.create_async(...)`.
Импорт PyTorch, проверка файлов и загрузка весов идут в фоновом потоке, чтобы
холодный старт не останавливал обмен с клиентом. Приватный сборщик создаётся
после загрузки; отменённая инициализация не оставляет открытый capture.
Прямой `MiniLMClassifier(...)` загружает модель синхронно и предназначен для
автономных инструментов/тестов, а не для запуска внутри работающего игрового цикла.

Доверенные critical/mandatory-события по-прежнему обрабатываются правилами.
Нейросеть оценивает остальные события. Неподдерживаемый вход, превышение 512
токенов, ошибка или тайм-аут дают переход к правилам с отдельной записью причины.
Вход не обрезается молча. На одну модель допускается одно незавершённое вычисление;
новые запросы не образуют очередь за зависшим потоком PyTorch.

## Логирование

По умолчанию файлы не записываются. Перед своим запуском можно включить запись:

```sh
export ACTOR_MINILM_CAPTURE_ROOT="$PWD/.local/minilm-captures"
```

Новая папка создаётся с правами `0700`, файл каждого агента — `0600`. Уже существующая
папка должна принадлежать текущему пользователю и иметь права `0700`. Лимит — 256 KiB
на строку и 64 MiB на файл. Ошибки и пропуски видны в `classifier.report()`.
Точный вход модели и его hash записываются вместе с версией весов, оценкой,
ответом до политики Router и временем обработки. Последующие записи показывают
решение Router, принятый ответ Brain, шаги плана, команды и результаты.

Наблюдения берутся только из уже полученного состояния этого агента. Истории SDK,
ключей доступа и глобального состояния другого игрока в сборщике нет.
Сырые игровые captures и переписки **не входят в публикацию**; `.local/` исключена из Git.
Ответ модели не является правильной меткой. Во время игры веса не меняются.

## Что проверено и чего пока не знаем

На 290 входах разработки v7 дала TP=67, TN=220, FP=2, FN=1. Это не независимая
итоговая оценка. Новых меток, проверенных человеком, — **0**.

После фиксации весов были проведены три игровых попытки. Две завершились,
третья остановилась с ошибкой Codex SDK. MiniLM управляла одной завершившейся
игрой; остальные две использовали Qwen. Их входы не участвовали в обучении v7.
Повторная проверка этой поставки сохранила признаки и ответы на всех 486 входах.

На 182 предварительно размеченных обычных событиях MiniLM не дала лишних реакций
и нашла один нужный пересмотр после убийства, который правила пропустили.
Положительный пример здесь только один: этого недостаточно для утверждения,
что модель лучше правил во всех играх или улучшает процент побед.
Все 245 входов с доверенным critical-правилом сохраняют исходное решение правила.
[Сравнение](evidence/rules-comparison.json).

В старом живом прогоне были собрание без зарегистрированных голосов и прерывания
Brain новыми репликами. Эта поставка не объявляет эти проблемы исправленными.
Приоритеты обсуждения/голосования требуют отдельной работы в Runtime.

## Проверки перед публикацией

Четыре независимых прогона на настоящем клиенте и сервере прошли проверку:

| Сценарий | Правила | MiniLM v7 |
| --- | --- | --- |
| Убийство → тело → собрание → голосование | 1 убийство, 1 репорт, 3 голоса, импостер изгнан | То же |
| Выполнение заданий | Завершены 8 заданий | Завершены 8 заданий |

Стратегии в этих прогонах были детерминированными fixture Brains. Это проверка
игрового подключения и отсутствия поломок в двух сценариях, не сравнение
качества стратегической LLM или процента побед. [Отчёт](evidence/live-acceptance.json).

В двух матчах MiniLM записаны 240 пар вход/ответ: 155 решений правил и 85
нейросетевых оценок. Восемь файлов закрыты корректно; пропусков, ошибок записи
и переходов на правила из-за ошибки модели не было. Чат доставлялся в сценарии
собрания и входит в обычные события модели. На этих новых матчах модель не обучали.

В начале проверки обнаружился разрыв heartbeat при синхронной загрузке PyTorch;
после исправления неблокирующей инициализации оба матча MiniLM прошли полностью.
Ранние неудачные попытки и исправление отмечены в отчёте, они не выдаются за успех.
Полный набор Runtime/launcher/модели: 1877 тестов и 120 подслучаев прошли,
8 необязательных проверок пропущены. [Протокол](evidence/publication-validation.json).
[Ревью кода](evidence/code-review.md).

## Дообучение

Сначала собрать новые captures, затем проверить метки человеком и отделить целые
матчи для проверки. Не делить реплики разных агентов одного матча между train и
validation. Для синтетики одна исходная ситуация и её переформулировки — одна группа.
Смешивать новые train-примеры с ранее проверенными случаями, чтобы не забыть их.

Формат строки JSONL: `input` — полный объект из `examples/`, `label` — целое 0/1,
`group` — идентификатор матча/семейства, `weight` — целое от 1 до 16 (необязательно).
Автор разметки, пояснение и статус проверки хранятся рядом, не внутри `input`.
Trainer проверяет пересечение групп, одинаковые тексты и противоречивые метки;
смысловые дубли всё равно требуют ревью.

```sh
.venv/bin/actor-minilm-train \
  --train /absolute/path/to/train.jsonl \
  --validation /absolute/path/to/validation.jsonl \
  --output "$PWD/.local/minilm-candidate" \
  --epochs 2 --learning-rate 0.000005 --batch-size 8 --device cpu

.venv/bin/actor-minilm-evaluate /absolute/path/to/held-out.jsonl \
  --run "$PWD/.local/minilm-candidate"
```

Trainer продолжает выбранные локальные веса (по умолчанию v7), не перезаписывает
исходную модель и не продвигает кандидата автоматически. Для его пробного
подключения: `ACTOR_MINILM_MODEL_RUN=/absolute/path/to/candidate`, внутри нужны
`report.json` и `model/`. Исторические приватные датасеты не опубликованы;
[манифест происхождения](evidence/training-data-manifest.json) содержит размеры,
политику исключений и контрольные суммы. Точный повтор исторического обучения
без самих данных и предыдущих весов невозможен.

Для других игр нужны адаптер разрешённых наблюдений и отдельная проверка данных;
качество переноса на другую игру пока не установлено.

## Производительность

Замеры на Apple M5 / Python 3.12, CPU с двумя потоками:

- Обработка обычного события Runtime с правилами и выключенной записью:
  медиана около 0,040 мс до изменений и 0,042 мс после.
- Полный путь MiniLM на коротком синтетическом входе: медиана 2,89 мс без записи
  и 2,91 мс с записью; тайм-аутов и переходов на правила в этом замере нет.
- В реальных матчах с четырьмя параллельными агентами путь оценки модели:
  медиана 16,98 мс, p95 47,25 мс, максимум 51,24 мс; это включает проекцию и
  ожидание рабочего потока, а не только вычисления нейросети.
- На 486 сохранённых игровых входах задержки измерены отдельно в
  [сравнении](evidence/rules-comparison.json), поле `inference_latency_ms`.

[Подробный замер](evidence/performance.json) содержит размеры выборок, p95,
задержку цикла событий и память. Это локальные пробы, а не гарантия для любого
компьютера. Правила без нейросети быстрее; цена модели оправдана только при
сохранении качества и уменьшении ненужных стратегических вызовов.
Повторить пробу провайдера из корня репозитория:

```sh
mkdir -p .local
.venv/bin/python classifiers/minilm/benchmarks/benchmark.py \
  --iterations 300 --output .local/minilm-performance.json
```
